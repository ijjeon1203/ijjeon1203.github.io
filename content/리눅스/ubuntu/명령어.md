### 명령어


리눅스
리눅스나 유닉스에서는 df 라는 명령으로 현재 디스크의 남은 용량 등의 정보를 얻을 수 있습니다.

메가바이트(MB)/기가바이트(GB) 단위로, 알아보기 쉽게 출력하기 위해서는

df -h

이렇게 -h 옵션을 붙입니다.

그리고
df -h -T
이렇게 -T 옵션을 붙이면 파일 시스템의 종류까지 출력

/dev/sda1 이 첫번째 하드 디스크 첫번째 파티션입니다. (스카시SCSI가 아닌 IDE 방식 하드의 경우에는 /dev/hda1)

- 하드디스크 전체 Size(사이즈)는 7.6 기가바이트
- Used(사용한 용량)는 435메가이고
- Avail(사용 가능한 용량)은 6.8기가이고
- 현재 6퍼센트 사용했습니다.



cat(catenate)
- 파일의내용을출력함
- 형식:$cat[옵션]파일_이름
- more
- 텍스트파일의내용을한페이지씩보고자할때사용
- 형식:$more파일_이름;$ls–l|more
- head
- 파일의앞부분의내용을확인하는명령어,default는10줄까지보여줌
- 형식:$head[옵션]파일_이름;$headtest.c
- tail
- 파일의뒤부분의내용을확인하는명령어,default는10줄까지보여줌
- 형식:$tail[옵션]파일_이름;$tailtest.c
- wc(wordcount)
- 파일내의라인,단어,문자의수를출력
- 형식:$wc[옵션]파일_이름;$wctest.c
cp(copy)
- 소스파일을다른파일혹은디렉터리에복사함
- 형식:$cp[옵션]소스_파일명목적_파일명(혹은디렉터리)
- mv(move)
- 소스파일을다른파일혹은디렉터리에이동함.단소스파일은원위치에서삭제됨.
- 형식:$mv[옵션]소스_파일명목적_파일명(혹은디렉터리)

cp,mv는 파일원본 유지

rm,chmod는 원본 파일 변경


- rm(remove)
- 파일이나디렉토리를삭제할때사용.디렉터리내에하위디렉터리가있다면–r옵션을사용하여야모든디렉터리삭제함
- 형식:$rm[옵션]파일명;$rm–r[추가옵션]디렉터리명
- chmod(changemode)
- 대상이되는파일의권한을변경할때사용
- 형식:$chmod[옵션]파일명;$chmod777test.c;chmodu- x,g+rtest.c
- chown(changeowner)
- 파일의소유자혹은/와소유그룹을변경
- 형식:$chown[옵션](소유자명:소유그룹명)(파일명);$chownhsptest.c;$chown:hsptest.c;
- chgrp(changegroup)
- 파일의사용자그룹을변경
- 형식:$chgrp[옵션][그룹][파일];$chgrpnetworktest.c

-  디렉터리(directory)/폴더(folder)

pwd(printworkingdirectory)

- 형식:$pwd

- 형식:$cd[디렉터리]
- mkdir(makedirectory)

- 형식:$mkdir디렉터리
- ls(list)
- 디렉터리의내용을리스트
- 형식:$ls–asl;$ls;$ls–a;$ls–s;ls–l;



- 특수파일(specialfile)
-  물리적인장치에대한표현
-  키보드(stdin),모니터(stdout),프린터등도파일로간주하여사용

-  상대경로명(relativepathname)
  -  현재작업디렉터리부터시작해서경로이름을적는것

~ : 홈디렉터리

입출력재지정및파이프
재지정(redirection)
- 표준스트림(standardstream)의흐름을변경하고자할때사용
- 기호>또는<를사용
- 출력재지정
- 명령어의표준출력내용을모니터에출력하는대신에파일에저장
- 형식:$명령어>파일
- 입력재지정
- 명령어의표준입력을키보드대신에파일에서입력받음
- 형식:$명령어<파일
- 파이프
- 한프로세스의출력을다른프로세스의입력으로처리하는등프로세스간데이터입출력을위해사용
주)재지정은프로세스의입력이나출력을파일로사용
- 형식:$명령어|명령어
- 재지정과파이프는조합이가능함


프로세스
- 실행중인프로그램을말함
- 유일한프로세스식별자인PID를가짐

프로세스 관련 명령어
ps(processstatus)
- 프로세스의상태를확인할때사용
- 형식:$ps[옵션]
- jobs
- 현재실행되는프로그램(프로세스)을확인할때사용
- 형식:$jobs
- fg(foreground)
- 현재background로실행중인명령어를foreground작업으로전환을할때사용
- 형식:$fg%작업번호;$fg%1
- bg(background)
- 현재foreground로실행중인명령어를background작업으로전환을할때사용
- Ctrl+C가아닌Ctrl+Z키를누르게되면프로세스가멈춤.이떄bg를사용할수있음
- 형식:$bg%작업번호;$bg%1
- kill
- 프로세스를강제적으로종료시킬때사용
- 형식:$kill[옵션]pid(혹은%작업번호);$kill3456;$kill%1
# 리눅스 명령어

grep
- 대상파일들을읽어서,해당패턴을검색하고,패턴을포함하는줄을출력
- 형식:$grep[- 옵션]patternfile_name1[file_name2]
- diff
- 두파일을줄단위로비교하여그차이를출력
- 형식:$diff파일1파일2
- split
- 하나의파일을일정한크기의여러개작은파일로분할
- 형식:$split[- 옵션]입력파일[출력파일]
- cmp
- 두파일이같은지비교함.두파일이같으면아무것도출력하지않고,두파일이서로다르면내용이다른위치출력
- 형식:$cmp파일1파일2

sort
- 텍스트파일을정렬필드를기준으로줄단위로오름차순정렬
- 형식:$sort[- 옵션]파일
- find
- 옵션의검색조건에따라대상디렉터리밑에서해당되는파일을모두찾아출력함
- 형식:$find디렉터리[- 옵션]
- 옵션은옆의테이블참조
- 예
- $find.- name*.c–print
- $find/- typed- print
- $find.- perm777- ls
- $find.- name*.c- atime+30- execls- l{}

- background처리명령어
- background에서주어진명령어들을처리하고foreground에서는다른작업을수행할수있음.

# 문서편집기
## vi
기본으로제공하는문서편집기
모드
입력모드:i,a,o,I,A,O를누른후텍스트를입력할수있는상태
명령모드(Esc모드):esc키를누른상태
콜론모드(Ex모드)- esc키를누르고,:(콜론)을입력한상태

- 형식:$vi파일명

시작은명령모드에서수행됨
- 명령모드는화면의마지막줄에서입력됨
vi에서빠져나오기및저장하기
- Ex모드에서수행
- :wq작업내용을저장하고종료(ZZ와동일한기능)
- :q아무런작업을하지않은경우의종료
- :q!작업내용을저장하지않고종료
- :w현재작업중인내용을저장.빠져나오지않음
- :w!강제로저장하기(read- only로열었을경우)
- :wnew_filename새로운파일이름으로저장하기
- 파일읽기
- :r[ead]filename현재위치에filename읽어들이기
- :100rfilename100줄이후에filename읽어들이기
- :$ r filename 맨끝줄이후에filename 읽어들이기
- 다중파일편집하기
- :efile1새로운파일(file1)을읽어편집
- :e!파일이름저장여부를점검하지않고파일변경
- :e#이전파일을다시열기
- 예기치않은시스템다운후되살리기
- vi- r되살릴수있는모든파일의이름을보여줌
- vi- rfilevi에디터를실행하여지정한파일을되살리는옵션

# Makefile
- C/C++프로젝트를빌드하기위한파일
- Makefile을사용하는장점
- 다중모듈프로그램으로구성된실행파일을만들때,일부파일이변경된경우에사용이편리함.즉변경된파일과그파일의의존관계에따라필요한파일만다시컴파일하여실행파일을만듦
ex)
하나의 파일을 컴파일하여 object파일을 생성하는 명령
gcc–cmain.omain.c- - - (1)
gcc–cfoo.ofoo.c- - - - (2)
gcc–cbar.obar.c- - - - (3)
여러 파일을 묶어서 실행파일 만들경우
gcc–otstmain.ofoo.obar.o
이러한과정을수행하여tst라는수행파일이만들어짐
- tst를구성하는*.c,혹은*.h중에한파일이바뀌는경우
- (1),(2),(3)중에하나이상과(4)를수행

이걸 편하게 하기 위해 makefile사용
tst:main.ofoo.obar.o
gcc–otstmain.ofoo.obar.o
main.o:main.c
gcc–cmain.omain.c
foo.o:foo.hfoo.c
gcc–cfoo.ofoo.c
bar.o:bar.hbar.c
gcc–cbar.obar.c
$make

makefile에서 사용하는 변수 이러한변수들을활용하여makefile을다시만들면,
- makefile예(dependency표현)
CC=gcc
CFLAG=- c
OBJS=main.ofoo.obar.o
TARGET=tst
$(TARGET):$(OBJS) tst:main.o foo.o build gcc - o tst
$(CC)- o$@$(OBJS)
main.o:main.c

foo.o:foo.hfoo.c
bar.o:bar.hbar.c
- $make

# CMAKE

하나하나 다 파일명을 쳐줘야
장점

- 의존성검사를하지만소스파일내부를분석해서의존성정보를스스로파악함
- 소스파일에헤더파일을추가하면,빌드부터의존성관계변화를자동으로추적되어헤더파일의변화까지추적하여빌드함.
cmakefile.tst의내용
ADD_EXECUTABLE(tstmain.cfoo.cbar.c)
- 이러한파일을만들고cmake명령을다음과같이수행함.
cmakecmakefile.txt
- 그러면앞의makefile과같은makefile이만들어짐
- makefile이만들어지면make명령어를수행하면tst수행파일이만들어짐

# 디버거 gdb(GNU debugger)
가장 대표적인 디버거
주요기능
- breakpoint설정
- 한줄씩실행
- 변수읽기및수정
- 함수찾기
- 추적(tracing)
- gdb사용을위한컴파일
- - g옵션을이용하여컴파일
- 예:$gcc–g–otstmain.cfoo.cbar.c
- gdb실행
- $gdb[실행파일]
- gdb를위한그래픽사용자인터페이스
- http://www.gnu.org/software/ddd

- l[파일명]:[함수명]지정된함수를프린트

- b[파일:]함수파일의함수시작부분에breakpoint설정
- b n n번줄에breakpoint설정
- b+n 현재줄에서n개줄이후에breakpoint설정
- b- n 현재줄에서n개줄이전에breakpoint설정
- info b 현재설정된breakpoint출력
- clear줄번호 해당breakpoint삭제
- d 모든breakpoint들을삭제
