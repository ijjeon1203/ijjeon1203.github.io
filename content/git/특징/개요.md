# 정의
Git은 어떤 폴더의 변천사를 기록하고 싶을 때 사용하는 도구


# 역사
- 2005년 **리눅스 커널의 개발을 위해서 만들게 된 형상 관리 시스템**이다.

# 목적( git 을 이용하는 이유)

- 주로 복잡한 **프로젝트의 워크플로우 관리를 간단하게 하기 위해**서 사용한다.
- 프로젝트가 충분히 복잡하지 않다면 이 장점을 느끼기 힘드나 프로젝트가 점점 양이 많아지고 복잡해지면 이 장점을 크게 느낄 수 있다.

문서를 저장하는데 Git 저장소를 쓴다면, 텍스트를 편집하며 이력을 관리하고 차이점을 확인하거나, 몇 명이서 공동 작업을 하기에도 좋을 것 같다

Git을 바탕으로 그 위에 무언가를 만들어 내는 등의 아주 특수한 활용을 목표로 할 때 유용한 내용

지적호기심

Git 내부 구조를 파헤치며 지적 유희를 즐기시려거나, Git 저장소를 활용한 모종의 서비스를 개발하시려는 분들께 유용



# 특징

- 변경사항처리하고 브랜치를 관리 
- git 은 새 버전을 복사할 때 변경되지않은 파일의 경우 그 참조만 만듦으로써 디스크 공간 절약 
- 대부분의 형상 관리 시스템과 다른 모든 디렉터리는 네트워크 접속이나, **중앙 서버와는 독립적으로 동작하는 완전한 이력 및 완전한 버전 추적 기능을 갖춘 형상 관리 시스템**이다.
- **처리 속도가 빠르며** Repository 의 **완전한 복사본을 로컬에 저장**이 가능하고 **일시적인 작업에 대한 이력 관리**가 쉽다.
- 하지만 CVS 나 Subversion 을 사용했던 개발자들에게는 불편함이 있을 수 있으며 또한 대용량의 소스 코드 관리에는 부적절
 
- 작업폴더에 깃저장소가 생긴다는 것은 이 기록물을 보관할 수 있는 지하실이 짜잔! 생긴다는 걸 의미
- 깃저장소와 함께라면 해당 폴더의 모든 역사를 기록하고 언제든 다시 꺼내볼 수 있어요.
- git은 사용자가 시키는것을 넘어선 일은 절대 하지 않음
- 사용자가 실ㅅ로 자신이 원하지 않는것을 시킬순있음


- git은 축적하는 시스템 
	- git은 항상 추가하는 방식으로 작업을 진행 
	- git 데이터 베이스에 있는 아이템은 손실되지않는 불변의데이터
	- 데이터는 절대로 변경되지않으며 오로지 추가만 될 뿐
