분리된 상태에서 커밋추가하려고 하진않을것 

git은 사용자가 예전 커밋을 체크아웃하는 대부분이 예전코드 검토지 변경하기위해서가아니라 가정 변경은 브랜치 

분리된상태에서의커밋 메모장으로사용
사용자는 실험적작업과 커밋 다른 브랜치를체크아웃함으로 커밋버릴수있음

잘못된 변경사항이 모든이들작업사본에침투한다던가 출시되는 상황보다 덜 위험 

git branch, git checkout -b 를통해 새브랜치로이동시키지만않는다면 고아나다름없음


만든커밋 새 브랜치에 유지하고 싶으면 체크아웃 명령에 -b 옵션 사용 하면됨 

분리된 head 상태에서다시 돌아오려면 브랜치를 체크아웃 

git checkout 브랜치 이름 아닌 어떤참조라도 다룰수있음

브랜치 이름과 동일한참조 체크아웃할수도 있음
- 의도하지않게 분리된상태가 될수 있음 
리모트 브랜치의 참조를 사용해 명령하면브랜치가 아닌 브랜치의헤드에 해당하는 커밋이 체크아웃됨 

# 방향성 비순환그래프 DAG directed acyclic graph

데이터 구조의 한종류

각개별노드가 다른노드가리키고 그런참조들이 정보의사슬구축 
작업이 진행되면서 커밋이 추가됨에 따라 나무뿌리처럼계속퍼져나가는모양으로 자라는 구조 

git 브랜치 시각화하는데 사용 

git 을 설명할때 보통 큰그림에초점맞춤

서로푸시풀하는저장소전체네트워크와브랜치가안팎으로흘러다니는전체시스템

정보과학관점 git 믿을수없을만큼아름다운 시스템 

사람들 변경 일으키고 프로젝트 한발자국씩 진화시키며 히스토리 만들어감 

그래프 단지프로젝트 다응버전의저장이나 변경ㅅ하ㅏㅇ공유에 있어서만 중요한게아님 

git을 통해 협업한히스토리는 그래프로 모델링할수있음
그러나이는일련의사건목록으로표현할수도있음 바로이야기
